1-Diferencias entre
	-Sistemas Distribuidos
		-Describe: Arquitectura de sistemas
		-¿Qué es?:
			-Conjunto de computadoreas trabajando juntas como un solo sistema.
		-Objetivo:
			-Distribuir:
				-Procesamiento
				-Almacenamiento
			|	-Recurso de equipos
		-Ejemplos:
			-Servidor A - de matrícula
			-Servidor B - de Biblioteca
			-Servidor C - Autenticación

	-Microservicios
		-Describe: "Estilo" de la arquitectura escogida y el tipo de software
		-¿Qué es?:
			-Una aplicación se divide en pequeños "servicios" independientes.
		-Objetivo:
			-Dividir una aplicación grande:
				-en partes pequeñas y autónomas
		-Ejemplos:
			-Servicio de consulta de usuarios
			-Servicio de consulta de productos
			-Servicio de consulta de pagos
			-Servicio de consulta de inventario
				-Comunicación: por medio de APIs
					-Ejemplo:
						-Cliente
							-API GateWay
								-Usuarios
								-Productos
								-Pagos
								-Inventario

	-Programación Web
		-Describe: Desarrollo de aplicaciones, accesibibles mediente un navegador
		-¿Qué es?:
			-Desarrollo aplicaciones que funcionan mediente tecnología web.
		-Objetivo:
			-Crear aplicaciones:
				-accesibles desde una navegador o internet.
		-Ejemplos:
			-Navetador
				-HTTP/HTTPS
					-Servidor Web
						-Aplicación
							-Base de Datos

2-Se explica: Arquitectura Distribuida vs Sistemas Distribuidos
	-Arquitectura D.
		-Diseño o modelo
		-Nivel: conceptual
	-Sistema Distribuido
		-Implementación
		-Nivel: operativo

2.1-Canalizada con el curso, ejemplos de puntos a tomar:
	-Arquitectura D. - objetivo
		-comunicación de componentes
		-cómo se ejecuta cada servicio
		-distribuye la información
		-maneja la seguridad
		-cómo escalar la arquitectura
		-cómo tolerar fallos
			
	-Sistema D.
		-la ejecuciòn de las tareas en varias computadoras
		-la "sharing" - compartición de recursos
		-"availability" - disponibilidada
			-soporte a miles o millones de usuarios
		-rendimiento
		-Funcionamiento:
			-Se espera que "Todos funcionan simultáneamente."
				-A veces existen ciertas condiciones que hacen que no sean simultáneos:
				-pueden existir "conflictos", "dependencias", "bloqueos", entre otros.
					-amerita un tipo de administración del funcionamiento de proceso para superarlos.

3-¿Toda Arquitectura D. es un Sistema D.?
R/No, porque puede quedarse solo como un diseño.

4-¿Todo sistema distribuido necesita de una arquitectura?
R/Sí, porquer todo Sistema D. se basa en alguna arquitectura, aunque sea sencilla.

5-Resumen de características de un Sistema D.
	-Transparencia
	-Escalabilidad
	-Tolerancia de Fallos
	-Concurrencia
	-Compartir recursos
	-Comunicación
